Amazon RDS for SQL Server
ルート証明書をWindowsの画面から登録する

PowerShellスクリプトを実行できない場合に、Windowsの証明書ウィザードで作業する手順です。

対象例：東京リージョン / rds-ca-rsa2048-g1　｜　更新日：2026年11月19日

この作業で行うこと

同梱の単独ルート証明書（.cer）を拇印で確認し、Windowsの現在のユーザーの「信頼されたルート証明機関」に登録します。AWSの複数証明書バンドルは直接インポートしません。

管理者権限は通常不要です。登録は作業したWindowsユーザーのみに適用されます。他のユーザーやPC全体には適用されません。
重要：この資料の対象例は ap-northeast-1 / rds-ca-rsa2048-g1 です。作業前に対象RDSインスタンスのCA識別子を管理者に確認してください。対象CAが異なる場合、この手順の証明書名・拇印をそのまま使わず作業を止めてください。

事前に準備するもの

  • 同梱の対象ルート証明書 rds-ca-rsa2048-g1-root.cer
  • 対象RDSインスタンスのCA識別子（AWSコンソールのDBインスタンス詳細で確認）
  • 管理者またはサポート担当から提供された対象ルート証明書の拇印（Thumbprint）

拇印は本手順書の対象例では D790 BBB6 61BA FA41 0182 9F10 3D63 9BEF A300 F9A4 です。空白の有無や大文字・小文字は問いません。配布時は対象CAの設定と必ず照合してください。

証明書バンドル内の証明書をすべて「信頼されたルート証明機関」へ入れないでください。登録するのは、名前が対象CAと一致する自己署名ルート証明書1件だけです。中間証明機関は登録しません。

操作手順

1

対象DBのCA識別子を確認する

AWS管理者に対象DBインスタンスのCA識別子を確認します。ここでは rds-ca-rsa2048-g1 が表示される場合の例を説明します。CA識別子が異なる場合は、作業せず管理者に確認してください。

2

同梱の単独証明書を確認する

この手順では、バンドルではなく、対象CAのルート証明書1件だけを含む rds-ca-rsa2048-g1-root.cer を使います。証明書の拇印は D790 BBB6 61BA FA41 0182 9F10 3D63 9BEF A300 F9A4 です。

拇印の確認は、証明書ファイルをダブルクリックして「詳細」タブの「拇印」を表示します。対象DBのCA識別子が rds-ca-rsa2048-g1 と異なる場合、または拇印が一致しない場合は作業を中止して管理者に確認してください。

配布元が不明な証明書を使わないでください。単独証明書はAWS公式RDSバンドルに含まれる証明書から対象ルートだけを取り出し、拇印を照合して用意しています。
3

証明書管理を開く

スタートメニューで ユーザー証明書の管理 を検索して起動します。見つからない場合は Win + R を押して certmgr.msc と入力し、Enterを押します。画面タイトルが「証明書 - 現在のユーザー」であることを確認します。

4

信頼されたルート証明機関を開く

左側で 信頼されたルート証明機関 → 証明書 を開きます。画面タイトルに「現在のユーザー」と表示されていることを確認してください。「コンピューター アカウント」や「ローカル コンピューター」のストアは選びません。

5

単独ルート証明書をインポートする

「証明書」を右クリックし、すべてのタスク → インポート を選びます。手順2で拇印を確認した rds-ca-rsa2048-g1-root.cer を指定します。証明書ストアは信頼されたルート証明機関を選択し、保存先が正しいことを確認して完了します。

この手順では単独のルート証明書だけを登録します。AWSの複数証明書バンドル（.p7b/.pem）はこのウィザードで直接インポートしないでください。
6

登録結果と拇印を確認する

インポート完了後、証明書管理画面で 信頼されたルート証明機関 → 証明書 を開きます。対象のルートCAが表示されることを確認し、開いて詳細タブの「拇印」が事前に確認した値と一致することを確認します。

対象証明書が1件表示され、拇印が一致すれば登録完了です。Power BI Desktopなど接続アプリをいったん完全に終了し、起動し直してから再接続します。

作業後の確認・困ったとき

  • すでに同じ証明書がある：拇印が一致すれば追加登録は不要です。
  • 拇印が一致しない／CA識別子が異なる：追加・削除を行わず、管理者に対象CAと証明書配布元を確認してください。
  • 「アクセスが拒否されました」：現在のユーザー用ストアを開いているか確認します。組織の端末制限がある場合は社内ITへ連絡してください。
  • 接続エラーが続く：証明書以外に、接続先名、ネットワーク、SQL認証、Power BIの接続設定などが原因のことがあります。エラー全文を添えて管理者へ連絡してください。
トラブル解消のために「証明書の失効確認を無効化」「サーバー証明書を検証しない」等の設定を有効にしないでください。登録した証明書の削除や別CAの登録は、管理者の指示に従ってください。
